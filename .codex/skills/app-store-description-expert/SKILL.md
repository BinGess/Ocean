# app-store-description-expert

## Overview

基于输入的 App 名称、核心功能、目标受众，生成高转化且合规的 App Store 文案。
将 ASO 产出与 2026 隐私合规提醒合并输出，减少被拒风险。

## 输入与预检

按以下顺序执行：

1. 接收用户输入：`App 名称`、`核心功能`、`目标受众`。
2. 自动检测输入语言；除非用户明确要求切换语言，否则保持与输入一致。
3. 扫描高风险宣传词：`免费`、`No.1`、`最强`（以及同义表达，如“第一”“顶级”“最佳”等）。
4. 若命中风险词，在最终结果的“专家避坑提醒”中添加 `⚠️ 风险警告`，说明可能触发夸大宣传或无法验证声明风险。

## 核心字段生成

严格按以下字段生成并做长度校验：

1. `App 名称 (30 字符内)`：品牌名 + 核心功能词。
2. `副标题 (30 字符内)`：一句话价值主张，不重复 App 名称中的关键词。
3. `关键词 (100 字符内)`：
- 仅用英文半角逗号 `,` 分隔。
- 去空格、去重复、去竞品词。
4. `推广文本 (170 字符内)`：突出最吸引人的卖点、活动或近期更新。
5. `建议分类`：给出主分类和次要分类，并与核心场景强匹配。
6. `应用描述 (1-3-5 结构)`：
- Hook：前三行直击痛点（折叠前可见）。
- 场景描述：给出 2-3 个真实使用场景。
- 功能列表：使用 Emoji 引导，列出 5 个核心功能点。
- 隐私声明：强调 2026 合规要点（如本地存储、无广告、最小化收集）。

若某字段超限，优先精简措辞并保留核心价值，不删除合规信息。

## 强制审核红线

始终执行以下约束：

- 禁止出现竞品平台词：`Android`、`Google Play`、`华为`（含变体）。
- 关键词格式只允许英文半角逗号 `,`，不允许中文逗号或其他分隔符。
- 必须提醒用户准备：`隐私政策网址` 与 `Privacy Manifest`。
- 必须提醒用户使用 `Xcode 26 (iOS 26 SDK)` 构建与提交。

## 语气风格切换

按 App 类型调整语气：

- 工具/效率类：专业、精简、逻辑清晰、可信赖。
- 游戏/社交类：热情、有节奏、具行动号召。

## Privacy Policy Engine

在“定制化隐私协议”部分按 App 特征动态生成条款：

1. 数据收集声明：
- 单机/离线 App：强调“全本地存储，不上传服务器”。
- 有账号系统：列出收集字段（如邮箱、手机号）。
2. 第三方 SDK 披露：
- 询问或基于上下文推断是否使用广告、统计、云服务 SDK（如 Firebase）。
- 未确认时，显式标注“待开发者确认”。
3. 用户权利路径：
- 提供查阅、更正、删除、撤回同意的联系或入口说明。
4. 未成年人保护：
- 包含 2026 儿童隐私与监护人机制条款。
5. 开发者联系方式：
- 预留占位符：邮箱、网站、数据请求渠道。

## 输出格式模板

严格按以下四段输出，不增删一级标题：

1. `基础元数据`
2. `应用描述`
3. `专家避坑提醒`
4. `定制化隐私协议 (New!)`

模板如下（用实际内容替换方括号）：

1. 基础元数据
App 名称：[生成的名称]
副标题：[生成的副标题]
关键词：[关键词1,关键词2,关键词3]
推广文本：[生成的推广文本]
分类信息：主要分类；次要分类；

2. 应用描述
[按 1-3-5 结构生成完整描述]

3. 专家避坑提醒
⚠️ 审核风险：[可能触发拒绝的点，如 4.1 准则、隐私声明不完整]
📦 技术准备：[演示账号、截图规格、隐私政策网址、Privacy Manifest、Xcode 26]

4. 定制化隐私协议 (New!)
标题：[App 名称] 隐私政策
核心条款：
- 数据零收集承诺（适用于本地 App）。
- 权限使用说明（仅说明必要权限及用途）。
- 无追踪声明（符合 App Tracking Transparency）。
- 数据本地化声明。
- 无第三方分享声明。

## 生成前自检

在输出前逐项检查：

1. 是否保持与用户输入语言一致。
2. 是否包含并仅包含四个一级输出段落。
3. 是否满足所有字符上限。
4. 是否移除竞品词与重复关键词。
5. 是否加入隐私政策网址、Privacy Manifest、Xcode 26 提醒。
6. 是否在命中风险词时给出明确风险警告。
