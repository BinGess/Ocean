# v1.6 深入分析功能改动与前后端协作说明

> 更新时间：2026-06-11（上一版：2026-06-07）
> 分支：`v1.6`
> 用途：说明 v1.6 客户端已经完成的页面、智能体与本地数据能力，以及需要服务端配合的工作。

## 0. 本次更新摘要（06-07 → 06-11 的变化）

上一版文档写于"智能体未配置、全是客户端占位"的阶段。这四天发生了大变化，**请优先读这一节**：

1. **六个 Coze 智能体全部上线**，客户端已直连调用（不再是固定模板）：NVC 分析智能体 ×1 + 五种深入方法各一个独立智能体 ×5。
2. **NVC 智能体整体更换为新实例（新旧并存）**：v1.6 不是在旧 NVC 智能体上改 prompt，而是新建了一个 NVC 智能体（新域名/Token/Project ID），新版已上线可用。**线上已发布的旧版 App 仍在调旧智能体**，v1.6 客户端配置的是新智能体——在 v1.6 发版且旧版本用户升级完成之前，**旧 NVC 智能体必须保持运行，不能下线**。
3. **意图分类方案变更**：上一版规划的"独立意图分类智能体"**作废**。分诊已合并进新版 NVC 智能体——NVC 输出里直接多一个 `recommended_method` 字段，客户端零额外请求拿到推荐。
4. **第三个方法升级**：`selfCompassion` 从"站回自己这边（Self-Compassion）"升级为"**自我关怀与滋养**（Self-Compassion & Savoring）"，双面机制：低谷面处理自责，高光面品味放大积极体验。`type` 枚举值不变。
5. **深入分析输出结构升级**：不再是四段文本，而是结构化拆解（开口第一句 / 情绪强度 / observed→truth 翻转卡 / 一句洞察 / 微行动 / 给自己的一句话）。`DeepAnalysisResult` 字段有新增（见 3.1），**旧字段全部保留，只加不删**。
6. **Pro 购买页**新增"深入分析"权益卡。
7. **当前智能体调用是客户端直连 Coze（过渡态）**，Token 在客户端 `.env` 中。上架前建议迁移到服务端代理（见 5.2），这是你后续介入的主要建议项之一。

**服务端需要配合的事，收敛为三件**（详见第 5 节）：

| 优先级 | 事项 | 一句话说明 |
| --- | --- | --- |
| P0 | Record 同步协议透传两个新字段 | `nvc.recommendedMethod`（字符串）+ `deepAnalyses`（数组），存储并原样返回即可 |
| P1 | 深入分析结果云端存储 | `deepAnalyses` 的增删改查与多设备同步（上一版 5.3 的方案仍有效，schema 已更新） |
| P2（上架前） | 智能体调用迁移到服务端代理 | 当前客户端直连 Coze，Token 打包在安装包里有安全风险 |

## 1. 当前结论

v1.6 已经完成"在 NVC 结果之后继续深入"的**完整真实链路**（不再是原型）：

1. 用户记录 → NVC 智能体分析（同时返回推荐的深入方法）。
2. NVC 结果页展示 5 种深入分析方法，推荐徽章按智能体返回值显示（智能体字段缺失时回退客户端关键词规则）。
3. Pro 用户选择方法后进入深入分析结果页：先显示本地占位内容，约 10 秒后被对应方法智能体的真实结果无感替换。
4. 深入分析完成后，结果回写到当前 NVC 结果页。
5. 同一条记录可以保存多种深入分析，之后从记录列表重新打开时仍可查看。

当前剩余的两个边界：

- **深入分析结果尚未接入服务端。** 仍使用 Hive 按记录 ID 保存在本机，不会跨设备同步（P0/P1 待办）。
- **智能体由客户端直连调用。** Token 与 Project ID 配置在客户端 `.env`（打包进安装包），上架前应迁移到服务端代理（P2 待办）。

现有 Record/NVC 服务端协议未被破坏；但客户端 Record 上传的 `nvc` 对象内**已新增可选字段 `recommendedMethod`**，服务端需要允许并透传（见 5.1）。

## 2. 页面层级已经完成的改动

### 2.1 保持不变的页面

- 首页语音输入页的核心流程不变。
- 文字输入页的核心流程不变。
- NVC 分析过程页不变。
- 原有 NVC 的"事实观察、感受、需要、行动 Tips"内容结构不变。

### 2.2 NVC 结果页

原来的 NVC 长浮层改为独立完整页面，并保留原有能力（展示原始记录、编辑四模块、改时间、分享、删除）。

NVC 结果下方"继续深入"区域：

- 横向滑动展示 5 种方法卡片，卡片显示产品名称和理论来源。
- **推荐徽章来源已切换**：优先使用 NVC 智能体返回的 `recommended_method`；字段缺失或值非法时回退客户端关键词规则（旧行为）。
- 推荐项自动滚动到可视区域。
- 用户先选择方法，再点击底部按钮进入结果页。

5 种方法现为：

| type | 页面名称 | 方法 | 理论来源 |
| --- | --- | --- | --- |
| `cognitiveReframe` | 想法校准 | CBT | 源自经典认知行为学派 |
| `releaseControl` | 放下控制 | ACT | 源自第三波认知行为疗法 |
| `selfCompassion` | **自我关怀与滋养** | **Self-Compassion & Savoring** | **源自自我关怀与正向心理学** |
| `boundarySupport` | 稳住情绪 | DBT | 源自第三波认知行为疗法 |
| `gentleRecovery` | 慢慢带回自己 | Behavioral Activation | 源自行为主义与 CBT 干预传统 |

> `selfCompassion` 是唯一"双面"方法：智能体会判定 `face`（`low` 低谷面=自我关怀 / `high` 高光面=品味滋养），页面氛围、文案、行动按钮随之切换。其余四个方法无 face 概念。

### 2.3 非会员链路

- "继续深入"标题旁显示 Pro 标记；5 张方法卡片半透明 + 锁图标。
- 点击卡片或底部"Pro 深入分析"进入 Pro 购买页。
- 权限判断复用 `ProSubscriptionService.hasProFeatureAccess`。
- **Pro 购买页已更新**：新增"深入分析"权益卡（放第一位），副标题同步改为"解锁深入分析与数据导出，让每条记录都多走一步"。

说明：当前 Pro 限制由客户端控制。智能体调用迁移到服务端后，服务端必须同步校验用户权益（见 5.2）。

### 2.4 深入分析结果页（本次重构）

页面有两套渲染，按数据自动选择：

**结构化新页面**（智能体返回结果走这套，从上到下）：

1. 方法名称大标题 + 专业方法名称和理论来源。
2. `selfCompassion` 显示 face 胶囊（"低谷时刻·站回自己这边" / "高光时刻·接住自己的好"）；其余方法显示方法概述。
3. **开口第一句**（`resonance`）：聊天气泡样式的共鸣句。
4. **情绪条**（`emotions`）：情绪词 + 强度小色条。
5. **翻转卡**（`observed` → `truth`）：上半部分是用户的原始视角（仅 CBT 和自我关怀低谷面划删除线），向下箭头，下半部分是翻转后的视角（暖色高亮块）。
6. **一句洞察**（`insight`，存储在 `groundedUnderstanding` 字段）。
7. **行动卡**（`oneSmallStep` + `microActionKind`）：kind 为 `savoring` 时按钮是"收进高光"，其余是"做一下"。
8. **给自己的一句话**（`steadySentence`）：引用样式卡片。

页面氛围色：自我关怀高光面为明亮暖黄，其余（含低谷面和四个方法）为暖米色。

**旧四卡页面**（兜底）：智能体未配置/调用失败时显示本地占位内容，结构同上一版文档（卡住的地方/更贴近的理解/一件小事/陪你站稳的话）。

进入页面的加载策略：**占位先行**——立即渲染本地占位内容 + 顶部细加载条"正在慢慢读你写的这条…"，智能体返回（实测约 10 秒）后整页无感替换；失败则保留占位 + 轻提示，不阻塞用户。

输入过短时（智能体返回 `enough_signal=false`）：只显示共鸣句 + 邀请用户多写一点，不硬给分析。

### 2.5 深入分析结果回写

（与上一版一致）结果以紧凑模块追加在"行动 Tips"下方；点击可重新打开（此时不会重新调用智能体）；同一方法 upsert、不同方法并存。

## 3. 客户端当前的数据实现

### 3.1 深入分析数据结构（已升级，旧字段全保留）

`DeepAnalysisResult` 完整 JSON 如下。**前 10 个是上一版已有字段，含义不变；后 9 个为本次新增**（智能体未返回时为 null/缺省，旧数据可正常反序列化）：

```json
{
  "type": "selfCompassion",
  "title": "自我关怀与滋养",
  "methodLabel": "Self-Compassion & Savoring",
  "theorySource": "源自自我关怀与正向心理学",
  "overview": "方法概述",
  "stuckPoint": "（兼容字段，现存放 observed 的内容）",
  "groundedUnderstanding": "（兼容字段，现存放一句洞察 insight）",
  "oneSmallStep": "微行动文案",
  "steadySentence": "给自己的一句话",
  "analyzedAt": "2026-06-11T10:00:00.000Z",

  "face": "low",
  "enoughSignal": true,
  "resonance": "开口第一句（共鸣句）",
  "emotions": [ { "name": "疲惫", "intensity": 75 } ],
  "observedLabel": "你对自己说的话",
  "observedValue": "「是不是我不行」",
  "truthLabel": "但其实",
  "truthValue": "事情多到一个人扛不动，是处境的问题",
  "microActionKind": "self_kindness"
}
```

新增字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `face` | string?，`low`/`high` | 仅 `selfCompassion` 有值，其余方法为 null |
| `enoughSignal` | bool，默认 true | false 表示输入过短，页面只渲染共鸣句 |
| `resonance` | string? | 开口第一句 |
| `emotions` | 数组 `{name, intensity}` | intensity 为 0-100 整数 |
| `observedLabel/Value` | string? | 翻转卡上半（各方法 label 不同，如 CBT 是"你脑中的结论"） |
| `truthLabel/Value` | string? | 翻转卡下半（如 CBT 是"事实是"） |
| `microActionKind` | string? | `self_kindness`/`savoring`/`thought_check`/`defusion`/`steady_express`/`tiny_recharge` |

### 3.2 NVC 对象新增字段

`Record.nvc` 内新增**可选**字段（这是 Record 同步协议唯一的 nvc 变化）：

```json
{
  "nvc": {
    "observation": "…",
    "feelings": [ … ],
    "needs": [ … ],
    "request": "…",
    "insight": "…",
    "recommendedMethod": "selfCompassion",
    "analyzedAt": "…"
  }
}
```

`recommendedMethod` 是 NVC 智能体的分诊结果，枚举只有 5 个值（同 2.2 表格的 type 列），可能为 null（旧记录/解析失败）。

### 3.3 本地临时存储

（与上一版一致）Hive `settings` box，Key `deep_analysis_v1_<recordId>`，Value 为 `DeepAnalysisResult` JSON 数组；创建/更新/删除记录时同步维护；兼容旧的单条对象格式。**仍是服务端能力上线前的临时兜底。**

限制同上一版：换设备/卸载不可恢复、云同步不携带、多设备状态可能不一致。

### 3.4 本次修复的一个持久化 bug（06-11）

`RecordModel.fromEntity` 的 nvc 映射是手写白名单，最初漏了 `recommendedMethod`，导致**历史记录重新打开时推荐徽章静默回退关键词路由**。已修复（[record_model.dart](../lib/data/models/record_model.dart) nvc map 中补充该字段）。服务端做 `nvc` 字段校验时请注意：**这个字段会出现在客户端上传的 payload 里，不要丢弃**。

## 4. 智能体现状（已全部上线）

共 6 个 Coze 智能体，全部经真实样本实测通过。配置在客户端 `.env`（**过渡态**，见 5.2）：

| 智能体 | 职责 | `.env` 配置组 |
| --- | --- | --- |
| NVC 分析（新版，全新实例） | NVC 四模块 + 分诊 `recommended_method` | `COZE_API_TOKEN / COZE_BASE_URL / COZE_PROJECT_ID` |
| 自我关怀与滋养 | `selfCompassion` 深入拆解（双面） | `COZE_DEEP_ANALYSIS_*` |
| 想法校准 | `cognitiveReframe` 深入拆解 | `COZE_DEEP_CBT_*` |
| 放下控制 | `releaseControl` 深入拆解 | `COZE_DEEP_ACT_*` |
| 稳住情绪 | `boundarySupport` 深入拆解 | `COZE_DEEP_DBT_*` |
| 慢慢带回自己 | `gentleRecovery` 深入拆解 | `COZE_DEEP_BA_*` |

### 4.0 NVC 智能体新旧并存（重要）

NVC 是**整体更换智能体实例**，不是原地改 prompt，目前两个实例并存：

| 实例 | 状态 | 谁在用 | 输出差异 |
| --- | --- | --- | --- |
| 旧版 NVC 智能体 | 运行中，**不可下线** | 线上已发布的旧版 App | 仅 NVC 四模块，无 `recommended_method` |
| 新版 NVC 智能体 | 已上线 | v1.6 客户端（`.env` 已切换） | 四模块 + `recommended_method` 分诊字段 |

由此带来的并存期影响：

1. 旧智能体的下线时机 = v1.6 发版后、旧版本用户基本升级完之后（可结合版本分布数据决定）。
2. 并存期服务端会同时收到两种 Record payload：旧版 App 上传的 `nvc` 不含 `recommendedMethod`，新版含——5.1 的"缺失视为 null、不误清空"必须兼容这两种来源。
3. 若做 5.2 的服务端代理迁移，代理的是**新版**实例；旧实例随旧版本 App 自然退役，不进代理。

调用方式（六个一致）：`POST https://<各自域名>.coze.site/stream_run`，Bearer Token，SSE 流式返回，客户端拼接 `answer` 增量后提取 JSON。单次耗时约 10 秒。

五个深入分析智能体的**输出 JSON 同构**（客户端一个解析器吃全部）：

```json
{
  "method": "cognitive_reframe",
  "enough_signal": true,
  "analysis": {
    "trigger": "客观还原这件事",
    "core": {
      "observed": { "label": "你脑中的结论", "value": "…" },
      "truth": { "label": "事实是", "value": "…" }
    },
    "emotions": [ { "name": "焦虑", "intensity": 80 } ]
  },
  "response": {
    "resonance": "开口第一句",
    "insight": "一句洞察",
    "micro_action": { "text": "…", "kind": "thought_check" },
    "self_statement": "给自己的一句话"
  }
}
```

仅 `selfCompassion` 额外多 `face`/`face_label` 两个顶层字段。客户端解析在 `coze_ai_service.dart` 的 `generateDeepAnalysis(methodType, transcription)` 通用入口（含强度 0-10/0-100 兼容、空值转 null、label/kind 按方法兜底）。

> 上一版 4.2 节的"客户端关键词推荐"现在只作为**兜底**保留：NVC 智能体字段缺失/非法时才生效。

## 5. 服务端需要配合的工作

### 5.1 （P0）Record 同步协议透传两个新字段

**意图分类智能体方案作废，不需要做分类接口。** 分诊已由 NVC 智能体完成，客户端直接拿到。服务端唯一要做的：

1. `Record.nvc` 对象允许并存储可选字段 `recommendedMethod`（字符串，5 个枚举值或 null），列表/详情/同步接口**原样返回**。旧记录该字段缺失视为 null。
2. 旧客户端上传的 nvc 不含该字段时，不要误清空已有值（建议字段级合并或整对象覆盖时以客户端为准——nvc 本来就是整对象提交）。

> 上一版 5.1 建议的字段名 `recommendedDeepAnalysisType` / `deepAnalysisRecommendationReason` **作废**：实际实现为 `nvc.recommendedMethod`，且 reason 字段已砍掉（页面没有展示位）。

### 5.2 （P2，上架前）智能体调用迁移到服务端代理

当前客户端直连 Coze，6 组 Token 都在 `.env` 并打包进安装包（flutter_dotenv 机制），解包可见——**测试期可接受，上架前需要收敛**。迁移时建议：

```http
POST /api/v1/analysis/deep
Authorization: Bearer <access_token>
Content-Type: application/json
```

请求（比上一版简化——五个智能体只吃原始记录文本，不需要传 NVC 结果）：

```json
{
  "recordId": "record-id",
  "type": "selfCompassion",
  "transcription": "用户原始记录",
  "locale": "zh-CN"
}
```

响应直接用 3.1 的 `DeepAnalysisResult` 完整结构（含新增字段）。

服务端处理要点（沿用上一版，仍然成立）：

1. 校验登录态。
2. 校验 `type` 枚举（5 个值）。
3. **校验 Pro 权益**；无权限返回明确错误码如 `PRO_REQUIRED`（迁移后服务端是权益的最终防线，客户端按钮只是体验层）。
4. 按 `type` 路由到对应 Coze 智能体（6 组配置迁到服务端保管），SSE 拼接 answer、提取 JSON。
5. 对缺失字段、超长内容和非法 JSON 做解析兜底（可参考客户端 `_parseDeepAnalysisResponse` 的兜底逻辑）。
6. 超时（建议 45-60s）、重试、限流、可观测日志。
7. 返回稳定错误码，不透传模型原始错误。

NVC 智能体同理可一并迁移（它现在也是客户端直连）。迁移完成后客户端把 `coze_ai_service.dart` 的直连实现切到服务端接口，页面层零改动。

### 5.3 （P1）深入分析结果云端存储

Record 模型增加可选数组字段 `deepAnalyses`，**schema 用 3.1 的新结构**（含 face/resonance/emotions 等全部字段，建议服务端按"不认识的字段也原样存储返回"处理，避免未来加字段再改协议）。

需要同步修改（与上一版一致，仍然成立）：

1. Record 创建/更新接口接收并保存可选 `deepAnalyses`。
2. 列表、详情、全量快照和增量同步返回该字段。
3. 删除 Record 时一并删除其深入分析。
4. 旧记录允许字段为 null/缺失/空数组；旧客户端 payload 不含该字段时不误清空。
5. 同一 `type` upsert，不同 `type` 并存；多设备冲突以服务端版本或 `updatedAt` 处理。

### 5.4 生成与保存的职责（更新后）

当前实际时序：

1. 客户端直连对应方法的 Coze 智能体生成结果（迁移后改为调 5.2 的服务端接口）。
2. 客户端展示，用户点"完成"确认。
3. 客户端通过 Record 更新接口保存确认后的 `deepAnalyses`（5.3 上线后生效；目前写本地 Hive）。
